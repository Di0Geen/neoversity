## Завдання 1. Видача решти

Для формування решти використано набір монет:

```text
[50, 25, 10, 5, 2, 1]
```

У файлі `task_1.py` реалізовано дві функції:

- `find_coins_greedy` — на кожному кроці обирає найбільший можливий номінал;
- `find_min_coins` — методом динамічного програмування знаходить мінімальну кількість монет.

Для суми `113` отримано однаковий результат:

```text
Жадібний алгоритм: {50: 2, 10: 1, 2: 1, 1: 1}
Динамічне програмування: {50: 2, 10: 1, 2: 1, 1: 1}
```

В обох випадках використано 5 монет.

### Порівняння ефективності

Позначимо:

- `n` — суму решти;
- `k` — кількість доступних номіналів монет.

| Алгоритм | Часова складність | Просторова складність |
| --- | --- | --- |
| Жадібний | `O(k)` | `O(k)` |
| Динамічне програмування | `O(n * k)` | `O(n)` |

Додатково проведено вимірювання для суми `100000`. Найкращий середній час одного запуску становив:

| Алгоритм | Час виконання, с |
| --- | ---: |
| Жадібний | `0.000000525` |
| Динамічне програмування | `0.024177533` |

Значення часу можуть трохи змінюватися залежно від комп'ютера та навантаження системи.

Для заданих номіналів обидва алгоритми знаходять оптимальний набір монет, але жадібний алгоритм значно швидше працює з великими сумами. Він виконує лише один прохід по списку номіналів, тому розмір суми майже не впливає на час його роботи.

Динамічне програмування обчислює результат для кожної проміжної суми від `1` до `n`, тому потребує більше часу та пам'яті. Його перевага полягає в універсальності: для довільного набору монет воно гарантує мінімальну кількість монет, тоді як жадібний підхід може дати неоптимальний результат.

Отже, для набору `[50, 25, 10, 5, 2, 1]` і великих сум доцільніше використовувати жадібний алгоритм.

## Завдання 2. Інтеграл методом Монте-Карло

У файлі `task_2.py` обчислюється визначений інтеграл функції:

```text
f(x) = (x + 1)²
```

на відрізку `[0; 2]`.

Метод Монте-Карло генерує випадкові точки всередині прямокутника, який охоплює область під графіком. Частка точок, що потрапила під криву, використовується для наближеного визначення площі.

Після генерації `1 000 000` випадкових точок отримано:

| Метод | Результат |
| --- | ---: |
| Монте-Карло | `8.659584` |
| Аналітичне обчислення | `8.666667` |

Абсолютна похибка методу Монте-Карло становить `0.007083`, а відносна — приблизно `0.0817%`.

Результат Монте-Карло близький до аналітичного значення, тому обчислення виконано правильно. Невелике відхилення є очікуваним, оскільки метод використовує випадкові точки. Зі збільшенням їх кількості результат зазвичай наближається до точного значення, але одночасно зростає час виконання програми.

## Висновок

Жадібний алгоритм є найефективнішим для видачі решти заданими номіналами, особливо при великих сумах. Динамічне програмування працює повільніше, проте підходить для наборів монет, у яких жадібний вибір не гарантує оптимального результату.

Метод Монте-Карло дозволив отримати наближене значення визначеного інтеграла з малою похибкою. Порівняння з аналітичним результатом підтвердило правильність реалізації.

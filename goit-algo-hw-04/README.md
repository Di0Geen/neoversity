# goit-algo-hw-04

Домашнє завдання №4 з алгоритмів та структур даних.

У цьому проєкті виконано три завдання:

1. Рекурсивне копіювання та сортування файлів за розширенням.
2. Побудова фракталу "сніжинка Коха" за допомогою рекурсії.
3. Порівняння сортування вставками, сортування злиттям і Timsort.


## Структура проєкту

```text
goit-algo-hw-04/
├── .gitignore
├── README.md

├── task_2.py
└── task_3.py
```

## Завдання 1. Рекурсивне сортування файлів

У файлі `task_1.py` реалізовано програму, яка рекурсивно проходить по вихідній директорії, копіює файли та розкладає їх у новій директорії за розширеннями.

Наприклад, файли з розширенням `.txt` потрапляють у папку `txt`, файли `.jpg` — у папку `jpg`.

Якщо файл не має розширення, він потрапляє в папку `no_extension`.

Програма приймає два аргументи:

- шлях до вихідної директорії;
- шлях до директорії призначення.

Якщо директорію призначення не вказати, буде використано папку `dist`.


## Завдання 2. Сніжинка Коха

У файлі `task_2.py` реалізовано побудову фракталу "сніжинка Коха".

Для побудови використано рекурсію та модуль `turtle`.

Користувач вводить рівень рекурсії, після чого програма малює фрактал.

Чим більший рівень рекурсії, тим складнішою стає сніжинка.


## Завдання 3. Порівняння алгоритмів сортування

У файлі `task_3.py` реалізовано та порівняно три алгоритми сортування:

- insertion sort;
- merge sort;
- Timsort.

Для вимірювання часу виконання використано модуль `timeit`.

Програма тестує алгоритми на різних наборах даних:

- випадковий список;
- відсортований список;
- список у зворотному порядку;
- список з малою кількістю унікальних значень.

Після запуску видно, що сортування вставками добре працює на маленьких масивах, але на великих працює повільніше через складність `O(n^2)`.

Merge sort працює стабільніше на великих масивах, бо має складність `O(n log n)`.

Найкращий результат зазвичай показує Timsort, тобто вбудоване сортування Python.

Timsort працює швидко, тому що поєднує ідеї сортування злиттям і сортування вставками. Він ефективно використовує вже відсортовані частини списку, тому на практиці часто працює швидше за прості власні реалізації.

Приклад результатів після запуску `task_3.py`:

```text
Array size: 1000
  random:
    Insertion sort  0.089827 sec
    Merge sort      0.008830 sec
    Timsort         0.000262 sec

Array size: 5000
  reversed:
    Insertion sort  0.416253 sec
    Merge sort      0.003458 sec
    Timsort         0.000017 sec
```

За цими результатами видно, що insertion sort значно сповільнюється на більших масивах, merge sort працює стабільніше, а Timsort є найефективнішим у більшості випадків.

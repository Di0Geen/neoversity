# Домашнє завдання `goit-cs-hw-06`

Фінальна домашня робота з курсу **«Computer Systems and Their Fundamentals»**.

Проєкт реалізує вебзастосунок на Python без вебфреймворків, який приймає
повідомлення через HTML-форму, передає їх TCP-серверу та зберігає в MongoDB.

Основні складові:

1. HTTP-сервер для сторінок, статичних файлів та обробки форми;
2. TCP-сервер для отримання повідомлень і запису в базу даних;
3. Docker Compose для запуску застосунку та MongoDB.

## Структура проєкту

| Файл | Призначення |
|---|---|
| `main.py` | HTTP- і TCP-сервери, обробка та збереження повідомлень |
| `index.html` | Головна сторінка |
| `message.html` | Форма надсилання повідомлень |

| `.dockerignore` | Виключення файлів із контексту збірки Docker |
| `.gitignore` | Виключення файлів із Git |
| `README.md` | Опис проєкту та команди запуску |

## Встановлення та запуск

Для запуску потрібен Docker із Docker Compose. На macOS і Windows
можна використовувати Docker Desktop.

У терміналі з папки проєкту виконайте:

```bash
docker compose up -d --build
```

Python і залежності встановлюються всередині образу застосунку.
Локальне віртуальне середовище для запуску через Docker не потрібне.

Перевірка стану контейнерів:

```bash
docker compose ps
```

Після запуску відкрийте: [http://localhost:3000](http://localhost:3000).

## HTTP-сервер

HTTP-сервер працює на порту `3000` та обслуговує такі маршрути:

| Маршрут | Призначення |
|---|---|
| `/`, `/index.html` | Головна сторінка |
| `/message`, `/message.html` | Форма повідомлення |
| `/style.css` | CSS-файл |
| `/logo.png` | Зображення логотипа |

Для невідомих маршрутів повертається `error.html` зі статусом `404`.
Форма надсилає POST-запит на `/message` з полями `username` та `message`.
Порожні поля або поля лише з пробілів не приймаються.

## TCP-сервер і MongoDB

HTTP- і TCP-сервери реалізовані в одному файлі `main.py` та запускаються
в окремих процесах через `multiprocessing`.

Алгоритм обробки повідомлення:

1. Користувач заповнює форму та натискає **Send**.
2. HTTP-сервер перевіряє дані та передає JSON-повідомлення через TCP на `127.0.0.1:5000`.
3. TCP-сервер перетворює отримані байти на словник і додає час отримання.
4. Документ записується в колекцію `messages` бази `messages_db`.
5. Після підтвердження запису HTTP-сервер повертає статус `303` і перенаправляє браузер на головну сторінку.

Якщо сховище недоступне або збереження не підтверджене, повертається статус `503`.
TCP-порт `5000` використовується всередині контейнера застосунку.

Приклад документа без службового поля `_id`:

```json
{
  "date": "2026-10-01 10:02:42.895827",
  "username": "Mukhailo",
  "message": "test"
}
```

Поле `date` формується через `datetime.now()` за часом середовища застосунку.
MongoDB автоматично додає поле `_id` до кожного документа.

## Перевірка

Перевірка головної сторінки та обробки невідомого маршруту:

```bash
curl -i http://localhost:3000/
curl -i http://localhost:3000/missing
```

Очікувані статуси — `200` та `404` відповідно.

Перевірка надсилання повідомлення:

```bash
curl -i --data-urlencode 'username=Михайло' --data-urlencode 'message=Перевірка застосунку' http://localhost:3000/message
```

Після успішного запису очікується статус `303`.

Перегляд повідомлень у MongoDB:

```bash
docker compose exec mongodb mongosh --quiet --eval 'db.getSiblingDB("messages_db").messages.find({}, {_id: 0}).toArray()'
```

Перегляд журналів застосунку:

```bash
docker compose logs --tail=50 app
```

Під час перевірки через Docker підтверджено запуск контейнерів і запис нового
повідомлення в MongoDB. Також виконано 15 автоматизованих тестів HTTP/TCP
із тестовою заміною MongoDB: перевірено маршрути, статичні файли, форму,
Unicode, некоректні дані, обмеження розміру та помилки збереження.

## Збереження даних

MongoDB використовує іменований volume `mongo_data`, підключений до `/data/db`.
Дані зберігаються поза файловою системою контейнера.

Для перевірки збереження повідомлень після повторного створення контейнерів:

```bash
docker compose down
docker compose up -d
docker compose exec mongodb mongosh --quiet --eval 'db.getSiblingDB("messages_db").messages.find({}, {_id: 0}).toArray()'
```

Після запуску MongoDB дочекайтеся статусу `healthy` у `docker compose ps`.
Попередні повідомлення мають залишитися в базі.

**Не використовуйте `docker compose down -v`, якщо потрібно зберегти дані:**
параметр `-v` видаляє volume разом із повідомленнями.

## Зупинка

Зупинити контейнери:

```bash
docker compose stop
```

Повторно запустити зупинені контейнери:

```bash
docker compose start
```
